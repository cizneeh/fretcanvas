# State Design Memo

## 方針
- 状態は「編集ドメイン」と「UI設定」に分ける。
- 編集ドメインは、指板上の実データとその編集履歴を扱う。
- UI設定は、表示・書き出し・適用条件のような操作文脈を扱う。

## 設計意図
- 責務分離により、機能追加時の影響範囲を小さくする。
- 依存方向を明確にし、store同士の密結合を避ける。
- UI設定の変更が編集ロジックに直接波及しない構造にする。

## 依存ルール
- 編集ドメインstoreは、設定storeを直接参照しない。
- 設定値はUI層で解決し、編集アクションへ引数で渡す。
  - 引数は純粋な関数で計算したいね〜〜
- これにより、同じ編集アクションを異なる文脈から再利用しやすくする。

## 将来拡張メモ
- 「特定ルールでノートを一括追加」系の機能が増える場合は、次を優先する:
  - storeは汎用のノート反映アクションを持つ
  - 追加対象の計算は純粋ロジックとして分離する
- 目的:
  - ルールごとのロジック肥大化を防ぐ
  - テスト容易性を高める
  - 拡張時の見通しを維持する
